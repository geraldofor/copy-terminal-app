# REQUISITOS — COPYFORGE

## Requisitos Funcionais

### RF-001 — Entrada de briefing do produto
O usuário deve informar: nome do produto, descrição, público-alvo, tom de voz, objetivo e detalhes específicos por template.

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/lib/copy-templates.ts`, `src/i18n/templates.ts`

### RF-002 — Geração de copy com IA
O sistema deve gerar copy utilizando as informações do briefing através do Google Gemini, com fallback local.

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/convex/gemini.ts`, `src/lib/copy-knowledge-base.ts`
- **Nota:** A geração inclui engine estratégico (análise → estratégia → copy → verificação de qualidade).

### RF-003 — Adaptação ao público
A IA deve adaptar a linguagem ao público informado, interpretando motivações, dores e objeções.

- **Status:** ✅ IMPLEMENTADO (no prompt do Gemini)
- **Arquivo:** `src/convex/gemini.ts` — seção Strategic Intelligence

### RF-004 — Adaptação ao canal
A copy deve respeitar o canal selecionado: Meta Ads, Google Ads, Instagram, TikTok, Reels, Shorts, E-mail.

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/convex/gemini.ts` (FORMATS), `src/lib/copy-templates.ts`

### RF-005 — Variações e reescrita
O sistema deve permitir gerar diferentes versões com 13 modos de reescrita: persuasiva, emocional, direta, premium, urgente, curta, conversacional, agressiva, Instagram, Meta Ads, Google Ads, 3 variações.

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/components/copy/CopyOutput.tsx`, `src/convex/gemini.ts` (REWRITE_MODIFIERS)

### RF-006 — Histórico e biblioteca
O usuário deve conseguir salvar, visualizar, buscar, filtrar e excluir copies anteriores.

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/components/copy/LibraryPanel.tsx`, `src/convex/copies.ts`

### RF-007 — Não invenção
A IA não deve apresentar como fato uma informação que não foi fornecida ou validada. Regras obrigatórias no prompt bloqueiam: depoimentos, estatísticas, resultados, certificações, descontos, bônus, garantias, preços, escassez, prazos inventados.

- **Status:** ✅ IMPLEMENTADO (no prompt do Gemini)
- **Arquivo:** `src/convex/gemini.ts` — seção MANDATORY RULES

### RF-008 — Sistema de créditos
1 crédito = 1 copy gerada. Sistema server-authoritative: consumeCredits sempre cobra exatamente 1 crédito. addCredits restrito a admins.

- **Status:** ✅ IMPLEMENTADO
- **Arquivo:** `src/convex/usage.ts`

### RF-009 — Pagamentos (fluxo manual)
O sistema deve criar pedidos manuais com código de referência. O admin confirma pagamento e libera créditos automaticamente.

- **Status:** ✅ IMPLEMENTADO
- **Arquivo:** `src/convex/manualPayments.ts`, `src/pages/Admin.tsx`

### RF-010 — Pagamentos (PayPal)
Integração com PayPal para assinaturas recorrentes e pacotes avulsos (Orders API + Subscriptions API).

- **Status:** ⚠️ PARCIAL — Configurado em sandbox, pendente ativação em live
- **Arquivos:** `src/convex/payments.ts`, `src/convex/subscriptions.ts`, `src/convex/paypal.ts`

### RF-011 — Autenticação
Login sem senha via OTP por e-mail. Suporte a visitante anônimo (25 créditos de boas-vindas).

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/convex/auth.ts`, `src/convex/auth/emailOtp.ts`, `src/pages/Auth.tsx`

### RF-012 — Internacionalização
Interface e copies em 3 idiomas: Português (pt-BR), Inglês (en-US), Espanhol (es-ES).

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/i18n/strings.ts`, `src/i18n/templates.ts`, `src/i18n/index.tsx`

### RF-013 — Painel administrativo
Admin pode: ver estatísticas, gerenciar usuários (promover/bloquear/excluir), ajustar créditos, ver pedidos manuais, confirmar pagamentos, configurar instruções de pagamento.

- **Status:** ✅ IMPLEMENTADO
- **Arquivo:** `src/pages/Admin.tsx`, `src/convex/admin.ts`

### RF-014 — Knowledge Base estratégica
Banco de conhecimento com 15 itens estratégicos categorizados (objective, audience, pain, desire, benefit, objection, angle, channel, format, rule) integrado ao motor de geração.

- **Status:** ✅ IMPLEMENTADO
- **Arquivo:** `src/lib/copy-knowledge-base.ts`

### RF-015 — Diagnóstico de engine
Banner de diagnóstico na interface mostrando: ENGINE (Gemini ou Local Fallback) e KNOWLEDGE BASE (Active ou Not Used).

- **Status:** ✅ IMPLEMENTADO
- **Arquivo:** `src/components/copy/CopyOutput.tsx`

### RF-016 — Rastreamento de origem
O sistema registra de onde o usuário veio (UTM source, referrer) para atribuição de tráfego.

- **Status:** ✅ IMPLEMENTADO
- **Arquivo:** `src/convex/admin.ts` (recordSignupSource), `src/lib/traffic.ts`

## Requisitos Não-Funcionais

### RNF-001 — Responsividade
A aplicação deve funcionar em desktop e dispositivos móveis.

- **Status:** ✅ IMPLEMENTADO — Layout responsivo com sidebar colapsável e chips mobile.

### RNF-002 — Performance
A interface deve responder rapidamente. Geração de copy: timeout de 30s no Gemini com fallback.

- **Status:** ✅ IMPLEMENTADO — Typewriter animation, Convex reativa, 3 modelos fallback.

### RNF-003 — Segurança
Chaves de API nunca expostas no frontend. Backend valida autenticação, créditos e autorização.

- **Status:** ✅ IMPLEMENTADO
- **Arquivos:** `src/convex/gemini.ts` (action server-side), `src/convex/usage.ts` (server-authoritative credits)

### RNF-004 — Acessibilidade
Sem requisito formal definido.

- **Status:** ❌ PENDENTE
