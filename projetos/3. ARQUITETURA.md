## Backend — Convex Schema

### Tabelas Principais

| Tabela | Descrição | Índices |
|---|---|---|
| `users` | Usuários (herda authTables) | `email` |
| `copies` | Copies salvas pelo usuário | `by_user_created` |
| `manualOrders` | Pedidos manuais pendentes | `by_user`, `by_status` |
| `settings` | Configurações (instruções de pagamento) | `by_key` |
| `subscriptions` | Assinaturas PayPal ativas | `by_user`, `by_paypal` |

### Campos do Usuário

```
users:
  name, image, email, emailVerificationTime, isAnonymous
  role: "admin" | "user" | "member"
  blocked: boolean
  credits: number          ← restante
  creditsTotal: number     ← total do plano atual
  generatedTotal: number   ← total gerado (lifetime)
  signupSource: string     ← UTM/origem
  signupReferrer: string   ← referrer URL
```

## Fluxo de Geração de Copy

```
Usuário clica "Gerar Copy"
    │
    ▼
[1] GeneratorPanel.generate(vals)
    │
    ├── consumeCredits()           ← Server: sempre cobra 1 crédito
    │   └── Valida: auth + user + !blocked + credits > 0
    │
    ├── Local fallback roda        ← template.generate(vals, locale)
    │   (copy-templates.ts)
    │
    └── generateWithGemini()       ← Action server-side
        │
        ├── Autenticação           ← getAuthUserId()
        ├── Validação user         ← api.users.currentUser
        ├── API key check          ← process.env.GEMINI_API_KEY
        ├── Knowledge Base         ← getKnowledgeForPrompt() ★
        ├── buildPrompt()          ← Monta prompt estratégico
        ├── callGemini() × 3       ← flash-lite → flash → 2.0-flash
        └── Retorna { ok, text, model }
            │
            ├── ok=true            ← output = texto Gemini
            └── ok=false           ← output = fallback local
    │
    ▼
[2] setResult(output) + setEngine(model) + setIsFallback(bool)
    │
    ▼
[3] CopyOutput exibe resultado
    ├── Banner: ENGINE + KNOWLEDGE BASE
    ├── Texto formatado (parseCopyText)
    ├── Ações: Copiar / Salvar / Editar / Reescrever
    └── Modos de reescrita (13 opções)
```


## Princípios de Arquitetura

1. **Componentes existentes devem ser reutilizados** — não duplicar shadcn/ui ou Convex providers.
2. **Uma nova implementação não substitui funcionalidade existente** sem verificar dependências.
3. **Backend é a fonte da verdade** — frontend nunca determina créditos ou autorização.
4. **Actions Convex** para toda chamada externa (Gemini, PayPal) — chaves nunca no frontend.
5. **Minimal changes** — editar arquivos existentes sempre que possível.

## Regra para Alterações

Antes de modificar uma parte importante:
1. Identificar dependências (arquivos que importam)
2. Verificar impacto (tipos, queries, mutations)
3. Implementar com o menor conjunto de alterações possível
4. Executar `bun convex dev --once && bun tsc -b --noEmit`
5. Verificar regressões
